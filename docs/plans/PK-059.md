## Objetivo

Secure issue/comment entry points before enabling them: verify the actor's current repository write permission, allowlist commands/profiles, ignore bot-triggered loops, and validate issue/PR/repository/branch identities

## Pasos

1. Crear gate confiable de lectura que parsea evento sin checkout de PR.
2. Consultar permisos efectivos actuales del autor, exigir write/maintain/admin y no confiar en author_association; en reruns comprobar también solicitante actual.
3. Verificar repo/IDs, issue frente a PR, estado, rama y comentario; ignorar bots y ediciones salvo diseño posterior explícito.
4. Parser cerrado de comandos/perfiles, límites de tamaño/frecuencia y fallo cerrado ante API o ambigüedad.
5. Serializar texto de issues, comentarios, diffs y archivos como datos; nunca interpolar a fuente shell o expresiones ejecutables.
6. Entregar secretos solo tras gate y separar dispatch/publicación privilegiados del agente y validación; rechazar forks.
7. Preparar fixtures adversariales y documentar amenaza y límites residuales de prompt injection.

## Validación y aceptación

- Read/triage, bots, permisos revocados, repo incorrecto y comandos desconocidos no llegan a agente ni secretos.
- Comillas, backticks, $(), Markdown y saltos de línea se tratan como datos.
- Código y política de autorización proceden de base confiable, no de PR/comentario.
