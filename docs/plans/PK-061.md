## Pasos

1. Definir estados, identidad estable, timeouts y cancelación por issue/PR.
2. Distinguir retry de feedback y consultar recursos existentes antes de crear.
3. Serializar y detectar head remoto cambiado sin perder commits humanos.
4. Retry autorizado con backoff acotado para fallos transitorios; scope/permisos no se reintentan automáticamente.
5. Informar diagnóstico y recuperación de fallo entre push y PR, y límites de notificación tras cancelación.
6. Mantener reconstrucción de contexto como base y resume como optimización.

## Validación y aceptación

- Timeout/cancelación/fallo parcial dejan estado recuperable.
- Retry tras push exitoso y PR fallido reutiliza rama sin duplicar.
- Concurrencia humana provoca parada segura, no overwrite.
