## Objetivo

Prevent an older CI run from automatically deploying after a newer commit

## Dependencias

- [PK-049](PK-049.md) · Procedencia del artefacto de deploy.

## Pasos

1. Agrupar CI por PR o ref de push para cancelar runs obsoletos sin colisiones entre ramas.
2. Antes de publicación automática y después de esperas/aprobaciones, comprobar source SHA contra head permitido de main.
3. Revalidar bajo serialización de Pages y documentar intervalo de carrera residual.
4. Definir rollback manual explícito, autorizado y auditable que admite artefacto antiguo exitoso pero no omite procedencia.
5. Simular CI A lento/B rápido y aprobación durante avance de main.

## Validación y aceptación

- A no reemplaza automáticamente a B por terminar tarde.
- SHA obsoleto se omite con motivo visible.
- Rollback exige intención/autorización y artefacto válido; run_id inválido se rechaza.

## Detalles del TODO que se deben conservar

- Review push concurrency in `ci.yml` (`run_id` currently gives each push its own group); Pages serialization alone does not guarantee freshness
- Check source SHA/freshness before automatic publication; define an explicit authorized rollback path that deliberately permits an older successful artifact
- Test out-of-order CI completion and manual deployment of an invalid run ID
