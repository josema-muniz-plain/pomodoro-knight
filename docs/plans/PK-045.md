## Pasos

1. Inventariar required checks y cómo GitHub los asocia a la revisión actual, distinguiendo head y merge ref de PR.
2. Elegir GitHub App de permisos mínimos y token corto para publicación; evaluar dispatch solo si demuestra checks vinculados correctamente y reconocidos por el ruleset.
3. Crear token solo en publicador aislado, sin reutilizar COPILOT_GITHUB_TOKEN.
4. Definir aprobación previa para ejecutar cambios no confiables cuando proceda, sin secretos de escritura en validación.
5. Publicar PR y segunda revisión; consultar eventos, SHAs, checks y mergeability para verificar que el resultado viejo no desbloquea el nuevo.

## Validación y aceptación

- Cada revisión publicada obtiene todos los checks requeridos aplicables a la revisión actual.
- Fallo o ausencia bloquean merge; validación previa/aprobación no sustituyen checks.
- No hay bypass de protección ni auto-merge.
