## Objetivo

Start a CLI task from an issue using an authorized trigger (e.g. `/agent` in an issue comment); fetch its title, body, and relevant comments, reuse the existing issue templates, and link the generated PR back to the issue

## Pasos

1. Reutilizar el flujo manual endurecido y sus jobs. Añadir `issue_comment: created` solo al cerrar revisión prioritaria; mantener `workflow_dispatch` para diagnóstico.
2. Definir gramática cerrada en primera línea, por ejemplo `/agent`, `/agent blacksmith` o `/agent coding-agent`; rechazar opciones/perfiles desconocidos. Aplicar PK-059 antes de usar secretos.
3. Consultar por API la issue del repo esperado: título, cuerpo, estado y comentarios paginados. Conservar disparador y contexto pertinente con IDs/autores/fechas/URLs; limitar tamaño, documentar selección/truncamiento y excluir ruido automático sin perder aceptación.
4. Reutilizar formularios existentes y secciones de petición, restricciones, aceptación y validación humana, sin plantillas paralelas. Los formularios son texto editable, no autorización.
5. Resolver perfil mediante tabla confiable: bug/feature de código a coding-agent; contenido ASCII/sprite a blacksmith; override autorizado solo si compatible. No derivar todo content a blacksmith: documentación, level data fuera de scope y tareas mixtas/ambiguas requieren rechazo o aclaración, sin ampliar permisos.
6. Materializar contexto JSON/Markdown y pasarlo como datos o argumento citado, nunca como fuente shell. Usar perfiles/políticas de revisión confiable.
7. Aplicar scope al artefacto completo según perfil: `blacksmith` solo `sprites/**`; `coding-agent` solo `src/**`, `test/**`, `scripts/**` con exclusiones de validadores autoritativos y políticas. La issue no levanta allowlists.
8. Crear identidad estable issue/tarea y rama dedicada, serializar por issue y detectar PR existente para no duplicar retries. En esta versión, comentarios en PR se rechazan o remiten a PK-058.
9. Publicar mediante job privilegiado un PR con `Closes #<issue>` y comentario de vuelta con enlaces PR/run, perfil y SHAs. Respetar validación humana y checks; reportar rechazo o ausencia de cambios sin PR vacío.

## Validación y aceptación

- Issue de sprite con plantilla content y actor write genera PR blacksmith solo en sprites y enlaces en ambos sentidos.
- Issue de código usa coding-agent; documentación/level data incompatibles y perfiles desconocidos se rechazan sin ejecutar agente.
- Tests cubren no autorizado, bot, comentario en PR, issue cerrada, repo incorrecto, inyección, paginación, límites de contexto y staged fuera de perfil.
- Dos triggers/retries no duplican PR; checks se ejecutan para revisión actual y no hay auto-merge.
