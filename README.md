# 🍅⚔️ PomodoroKnight

> Focus. Complete pomodoros. Forge your tomato knight.

**PomodoroKnight** is a Pomodoro session web app where each completed session makes your character stronger: a **tomato knight** drawn entirely in **ASCII**.

## 🎯 The project's real purpose

The app is an excuse. The goal is to **practice [GitHub Agentic Workflows (gh-aw)](https://github.com/github/gh-aw)** in a repo designed to give agents real work to do:

- **Data-driven** content (`.txt` sprites, levels in JSON) → every contribution is a small, reviewable PR.
- ASCII → everything is text, **diffable**, and can be generated by agents.
- Tests + sprite validation in CI → automated feedback and failures to diagnose.

It also serves as a **lab for the [GH-600: Developing in Agentic AI Systems](https://learn.microsoft.com/en-us/credentials/certifications/resources/study-guides/gh-600) certification**. The exam is very practical (reading YAML, JSON, logs, and agent configuration), so each topic is practiced using a real artifact from the repo. See [GH-600 map](#-gh-600-map).

## 🧩 Features (MVP)

- 25/5 Pomodoro timer.
- Each completed pomodoro awards **XP**.
- When you level up, the tomato evolves visually (cosmetic only, for now).
- Progress saved in `localStorage` (no backend or accounts).
- Basic anti-cheating: switching tabs or pausing for too long invalidates the pomodoro.
- 100% ASCII UI: large digits, progress bars `[#####.....]`, frames.

## 🎨 ASCII art rules

1. **Fixed grid**: sprites are at most **24 columns × 10 rows**.
2. **Printable ASCII only** in sprites (no emojis: they break alignment).
3. Use a fixed monospaced font loaded by the web app.
4. Sprites live in **`.txt`** files with a metadata header (level, name).
5. Everything is validated with `npm run validate:sprites` in CI.

## 🤖 Planned agentic workflows

| Workflow | Trigger | What it does |
|---|---|---|
| **Issue Triage** | `issues: opened` | Labels issues (bug / content / feature) and asks for missing information |
| **CI Doctor** | Failed `workflow_run` | Analyzes logs and proposes a fix |
| **Blacksmith** `/forge` | Issue command | Generates a new sprite and opens a PR |
| **Sprite Preview** | `pull_request` | Comments with a rendered preview of the sprite on the PR |
| **Weekly Chronicle** | `schedule` | Weekly recap in an epic tone |

## 🎓 GH-600 map

> gh-aw **isn't covered by the exam**. That's why this repo combines gh-aw with native Copilot features (agents, CLI, cloud agent, hooks).

| Domain | Weight | Where it's practiced in the repo |
|---|---:|---|
| **D1** Architecture and SDLC | 15–20% | Issue → branch → PR → checks → review flow; agents with varying levels of autonomy |
| **D2** Tools and environment | 20–25% | `.github/workflows/*` (CI, deploy, lab), `.github/agents/*.agent.md`, MCP, `copilot -p`, `copilot-setup-steps.yml` |
| **D3** Memory and state | 10–15% | Copilot CLI sessions (`--resume`, `session-state`), handoffs via artifacts and PRs |
| **D4** Evaluation and tuning | 15–20% | Injected failures + `docs/incidents.md`, artifacts, `$GITHUB_STEP_SUMMARY` |
| **D5** Multi-agent | 15–20% | Review/audit/consolidate pipeline, `matrix.agent`, `concurrency` |
| **D6** Guardrails | 10–15% | Rulesets, environments with approval, `preToolUse` hooks, CodeQL, secret scanning |

Target `.github/` structure:

```text
├── copilot-instructions.md
├── instructions/sprites.instructions.md
├── prompts/review-sprite.prompt.md

├── agents/{sprite-reviewer,blacksmith,orchestrator}.agent.md

    ├── actions-lab.yml           # contexts, inputs, if:, workflow_call
    ├── copilot-setup-steps.yml   # cloud agent environment
    └── *.md / *.lock.yml         # gh-aw workflows
```
